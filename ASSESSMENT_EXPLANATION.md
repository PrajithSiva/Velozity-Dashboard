The hardest part of the project was making sure that each user could access only the data they were supposed to see. Since Admins, Project Managers and Developers have different permissions, I had to handle authorization carefully at the backend level. Instead of fetching a project or task first and checking the user afterward, I included the user’s role and ownership directly in the database query. This also helped prevent users from accessing another user’s projects just by changing an ID in the URL.

For the real-time activity feed, I used Socket.io. When a task status changes, the update, activity record and related notification are saved first. Only after the database transaction succeeds is the activity sent through Socket.io. Users receive updates based on their role and access — for example, through a project room, admin room or their personal room. The server checks project access before allowing a user to join a room, so the frontend does not have to receive and filter unrelated events.

One thing I would do differently is improve the presence system. Currently, online users are tracked in memory, which works well for a single server. If I were scaling the application, I would use Redis so that online status remains consistent across multiple backend instances.
